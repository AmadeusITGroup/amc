# Compatibility with the standard containers

The amc containers have the interface of their standard counterparts, so that most code switches from `std::vector` to `amc::vector`, or from `std::set` to `amc::FlatSet`, by changing the type only. This page lists what is guaranteed to behave the same, and every known observable difference.

- [Vectors](#vectors): `amc::vector`, `SmallVector`, `FixedCapacityVector` vs `std::vector`
- [inplace_vector](#inplace_vector): `amc::inplace_vector` vs C++26 `std::inplace_vector`
- [Sets](#sets): `FlatSet`, `SmallSet` vs `std::set`
- [SmallSet iterator invalidation](#smallset-iterator-invalidation)

The sizes are given for x86-64 with libstdc++.

## Vectors

### Same as std::vector

- The member types, constructors, assignments, element access, iterators, capacity and modifier functions of C++17 `std::vector`, with `emplace_back` returning a reference. From C++20: `operator<=>` (with the synthesized three-way comparison for types only providing `operator<`, and only for elements which can be compared: `std::three_way_comparable` is `false` for a vector of non-comparable elements), `erase` and `erase_if`. From C++23: `insert_range`, `append_range` and `assign_range`.
- The overloads taking a range of iterators only accept input iterators: `amc::vector<double> v(2.0, 3.0)` has 2 elements of value 3.
- `amc::vector` accepts an element type which is incomplete where the vector is declared, like `std::vector` from C++17: `struct Node { amc::vector<Node> children; };`.
- Arguments referring to elements of the vector itself are handled, as the standard requires: `v.push_back(v[0])`, `v.insert(pos, v.back())`, `v.emplace(pos, v[i])`, `v.assign(n, v[0])`.
- Single pass input iterators are read once.
- `vector(n)` and `resize(n)` value-initialize the new elements (`int` elements are zeroed).
- `at` throws `std::out_of_range`.
- Allocators: `propagate_on_container_copy_assignment`, `_move_assignment` and `_swap`, `select_on_container_copy_construction` and `is_always_equal` are honored, stateful allocators work, and memory is only exchanged between equal allocators.
- Moved-from vectors are empty (if their allocators are equal or propagate).
- Iterator invalidation of `amc::vector` follows the rules of `std::vector`.

Notes:

- The relocation of trivially relocatable types is the point of the library: it is only observable for types which [declare themselves trivially relocatable](containers.md#trivially-relocatable-types), whose move constructors and destructors are then skipped when elements move around. Trivially copyable types behave exactly as with `std::vector`.
- A `size_type` of `std::size_t` gives the limits of `std::vector`: `amc::vector<T, amc::allocator<T>, std::size_t>`. GCC and Clang warn about narrowed counts with `-Wconversion`, MSVC with `/W4`.
- `std::allocator<T>` can be passed as allocator, at the cost of the `realloc` growth path.

## inplace_vector

`amc::inplace_vector<T, N>` is a `FixedCapacityVector<T, N, BadAllocGrowingPolicy, std::size_t>`, which mimics C++26 `std::inplace_vector` with the differences of [FixedCapacityVector](#differences-with-stdvector) above.

| Feature                                                                              | `std::inplace_vector`                                                      | `amc::inplace_vector`        |
| ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- | ---------------------------- |
| `size_type`                                                                          | `size_t`                                                                   | same                         |
| Exceeding the capacity                                                               | `std::bad_alloc`                                                           | same                         |
| `try_push_back`, `try_emplace_back`, `unchecked_push_back`, `unchecked_emplace_back` | yes, `try_` ones return `nullptr` when full, `unchecked_` ones a reference | same                         |
| `try_append_range`, `append_range` (C++23)                                           | yes                                                                        | same                         |
| `capacity()`, `max_size()`                                                           | `static constexpr`                                                         | non-static member functions  |
| `constexpr`                                                                          | yes                                                                        | no                           |
| Trivially copyable if `T` is                                                         | yes                                                                        | no                           |
| `inplace_vector<T, 0>`                                                               | empty                                                                      | stores its capacity and size |
| `std::from_range` constructor                                                        | yes                                                                        | no                           |
| `allocator_type`, `get_allocator()`                                                  | no                                                                         | yes, an empty tag            |

## Sets

### Same as std::set

- The member types, constructors, assignments, lookups and modifiers of C++17 `std::set`: insertion with and without hint, `emplace`, `emplace_hint`, `extract` and `insert` of node handles, `merge` (of temporaries too), `swap`, `key_comp`, reverse iterators. From C++14: heterogeneous `find`, `count` (and `lower_bound`, `upper_bound`, `equal_range` for `FlatSet`) with a transparent comparator. From C++20: `contains`, `erase_if`, `operator<=>`. From C++23: `insert_range`.
- Elements are unique and constant: like the ones of `std::set`, iterators only give `const` access, although the `reference` and `pointer` member types are not `const`.
- `swap` is `noexcept` (also for `std::is_nothrow_swappable`) when the elements are not stored inline.
- The comparator may be stateful, a function pointer or a `final` class.
- Comparison operators give the results of `std::set` (for `SmallSet`'s `operator==`, as long as `==` implies equivalence).
- Insertion of an element already present, or of an empty node, has no effect.
- Moved-from sets are empty.

### SmallSet iterator invalidation

In the small state, the elements of a `SmallSet` are stored in a vector: iterators, references and pointers are invalidated like the ones of a vector. In the large state, they follow the rules of `SetType` (any insertion or erasure may invalidate them with a `FlatSet`). Unlike with `std::set`, `end()` is not stable: do not keep it to compare it later with the result of a `find`, or in an erasure loop.

| Operation                                                                                    | Invalidated iterators                                                                                      |
| -------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Insertion in the small state (`insert`, `emplace`, `merge`...)                               | `end()`                                                                                                    |
| Insertion making the set grow beyond `N` elements, `merge` from a large set into a small one | all of them, including `end()` and the ones to pass as hints: the elements are moved to `SetType`          |
| Erasure in the small state (`erase`, `extract`, `erase_if`, `clear`, being merged from)      | the ones to the erased elements and to the following ones, which are shifted, and `end()`                  |
| Erasure emptying a large set (`erase`, `extract`, `erase_if`, `clear`, being merged from)    | `end()`: the set becomes small again                                                                       |
| Move construction or move assignment from a set in the small state                           | the ones to its elements: they are relocated to the other set, the iterators do not follow them            |
| `swap` of a set in the small state                                                           | the ones to its elements: they are exchanged between the inline storages, the iterators do not follow them |

For instance, this loop, valid with a `std::set`, must compare `it` with `s.end()` at each step with a `SmallSet`:

```cpp
for (auto it = s.begin(), last = s.end(); it != last;) {  // 'last' may be invalidated by 'erase'
  it = pred(*it) ? s.erase(it) : std::next(it);
}
```

`erase_if(s, pred)` (C++20) does the same in a single pass.
